“R42의 탐지율을 알려 주고, 이 시험 전 장비 준비 조건도 확인해 줘.” 탐지율은 시험 데이터의 숫자 필드로 구할 수 있다. 준비 조건은 문서 본문에 있다. 과거 판본이나 다른 시험에는 문장 자체가 질문에 더 가까울 수 있다. 들어온 문서를 버전과 시험으로 좁히고, 질문한 절에서 근거를 찾았다.

NCP-AAI 학습 가이드 6.1–6.5는 임베딩과 하이브리드 검색을 포함한 RAG, 벡터 데이터베이스, 기업 데이터 ETL, 데이터 품질·전처리·증강, 구조화 및 비구조화 자료를 연결하는 방식을 다룬다. 공식 웹 비중은 10%다. [공식 출제표](https://www.nvidia.com/en-us/learn/certification/agentic-ai-professional/#exam-blueprint) · [공식 학습 가이드 6장](https://dam-cdn.nvd.orangelogic.com/AssetLink/64tei188l3tt132l265u1ipjoexdl1p5.pdf#page=9)

## 1. 원문을 가져와 검색 가능한 단위로 만들기

ETL에서 추출은 문서와 측정 레코드를 읽어 오는 단계다. 변환에서는 시험 ID와 날짜를 표준 형식으로 바꾸고, 문서를 절 또는 표 단위로 나누고, 원본 ID와 접근 범위를 붙인다. 적재에서는 원본 레코드와 검색 조각을 연결한다. 비슷한 문장이 여러 판본에 있어도 어느 판본에서 얻었는지 남겨야 한다.

{{< mermaid >}}
flowchart TD
    A["시험 기록과 안내 문서"] --> B["정규화 · 시점과 품질 검사"]
    B --> C["문서 절, 버전, 출처 ID 적재"]
    D["사용자 질문"] --> E["시험, 권한, 현재 버전으로 제한"]
    C --> E
    E --> F["단어와 벡터로 후보 순위 계산"]
    F --> G["절과 적용 조건을 대조"]
    H["시험 DB · 정확한 결과값"] --> I["근거와 결과를 연결"]
    G --> I
{{< /mermaid >}}

예제는 문서 ID, 시험 ID, 유효 시작 날짜, 종료 날짜, 절의 종류를 둔다. `valid_from ≤ 기준일 < valid_until`을 사용하며, 종료값이 없으면 현재 열린 구간으로 본다. 수집 시각, 문서가 효력을 갖는 날짜, 질문 시점은 다른 정보다. 앞으로 적용할 판본을 미리 받아도 현재 요청에는 아직 효력이 없을 수 있다.

표가 들어 있는 원문을 잘게 자를 때는 열 이름과 단위를 행과 함께 남긴다. 미터와 센티미터가 섞이거나, 상위 제목에 있는 적용 조건이 하위 덩어리에서 빠지면 검색 결과만 읽고 잘못 판단하기 쉽다. 동의어나 손질한 검색어를 보강해도 원문 인용 위치는 유지한다. 평가용 문서를 이용해 유사한 학습 문장을 만들면 평가에서 새 자료를 보는지 판단하기 어려워지므로 자료를 어떤 기준으로 분리했는지도 기록한다.

## 2. 단어 검색, 벡터 검색과 재정렬

단어 검색은 특정 시험 ID와 드문 제품명처럼 정확한 텍스트에 강하다. 임베딩 검색은 같은 내용을 다른 단어로 쓴 질문을 찾을 수 있다. 두 점수의 단위가 다르므로, 예제에서는 순위 기반 결합인 RRF를 썼다. 각 목록에서 r위인 문서에는 `1 / (60 + r)`을 더한다. 여기서 단어 점수는 단어 교집합의 크기이며 BM25의 문서 길이와 단어 빈도 가중치는 사용하지 않았다. [Reciprocal Rank Fusion 원 논문](https://research.google/pubs/reciprocal-rank-fusion-outperforms-condorcet-and-individual-rank-learning-methods/) · [블로그의 RAG와 재정렬 실습](/agentic-ai/rag/)

검색 결과를 생성에 사용할 때는 후보를 답변과 함께 보낸 뒤, 어떤 문서가 각 주장을 지지하는지 확인한다. 원 논문의 학습 방식과 서비스에서 이미 준비한 모델을 연결하는 방식은 구현 범위가 다르다. 이 글의 실습은 검색 순위와 마지막에 확인한 근거를 비교한다. [RAG 원 논문](https://arxiv.org/abs/2005.11401)

## 3. 벡터 DB에서 바꿀 조건과 측정할 값

작은 문서 집합은 질문 벡터와 모든 후보를 직접 비교할 수 있다. 후보가 커지면 HNSW처럼 가까운 벡터의 이웃을 그래프로 연결해 일부만 탐색할 수 있다. 탐색 폭을 넓히면 정답 후보를 얻을 가능성과 함께 작업량도 증가할 수 있다. 실제 성능 표에는 데이터 개수, 벡터 차원, 인덱스 구성, 필터 조건, K와 하드웨어를 같이 적는다. [HNSW 원 논문](https://arxiv.org/abs/1603.09320)

| 지표 | 비교 기준 |
|---|---|
| 근사 검색 회수율 | 동일 범위를 전수 비교한 결과와 근사 인덱스가 겹치는 정도 |
| 업무 근거 회수율 | 사람이 정의한 정답 절이 상위 K개에 들어오는지 |
| 필터 후 후보 수 | 권한, 기간, 시험 ID를 적용한 뒤 검색에 들어간 문서 수 |
| 지연과 저장 비용 | p50·p95, 인덱스 구축 시간, 저장소와 메모리 크기 |

상위 K를 먼저 뽑고 다른 사용자의 자료와 구버전을 빼면, 순위가 낮던 접근 가능한 후보까지 빠질 수 있다. 접근 권한은 실행 서비스가 정하고, 가능한 경우 범위를 먼저 좁힌다. 임베딩 모델의 버전을 바꿀 때는 현재 질문과 원문을 같은 모델 조건으로 매핑하는지 확인한다. 이번 실습에서는 SQLite와 코사인 전수 검색을 사용했다.

## 4. 현행 문서에서 오답이 먼저 올라온 경우

[knowledge_lab.py](knowledge_lab.py)에 과거 준비 절, 현재 준비 절, 현재 정리 절, 다른 시험의 준비 절, 날짜가 잘못된 문서까지 다섯 행을 넣었다. 날짜 오류 행은 적재에서 제외한다. 질문은 `How should I warm up the hardware before the test?`다. Python 3.13.18, Ollama 0.40.11, `all-minilm:22m`에서 실행했다.

```bash
ollama pull all-minilm:22m
python3 knowledge_lab.py
```

| 검색 범위 | 임베딩 1위 | 결합 순위의 첫 후보 |
|---|---|---|
| 적재된 전체 문서 | 다른 시험의 준비 절 `d-other` · 0.8727 | `d-other` |
| R42와 현재 유효 기간으로 검색 | 정리 절 `d-decoy` · 0.5997 | `d-decoy` |

잘못된 날짜의 `d-invalid`는 적재되지 않았다. 조건에 맞는 시험과 버전으로 골라도, 질문에 나온 `warm up`이 시험 후 정리 절에 있어서 1위였다. 현행 준비 절 `d-current`의 임베딩 점수는 0.5377이었다. 이 케이스의 업무 조건은 “시험 전 준비”다. 절이 `setup`이고 시험 ID와 기간이 맞는 기록을 별도로 조회했다.

## 5. 측정값과 안내 문서의 출처를 나누기

마지막 SQL 조인으로 합성 측정 레코드 R42의 탐지율 84.0%와 현행 준비 절 `d-current`를 얻었다. 준비 절에는 측정 전에 하드웨어를 열적으로 안정화하라고 적혀 있다. 옛 판본에 있던 20분을 현행 자료에 덧붙이지 않았다. 답변을 만들 때 수치의 출처는 시험 결과 레코드, 준비 조건의 출처는 문서 절로 따로 보관할 수 있다.

새 업무에서 요구하는 절 종류를 항상 알 수는 없다. 질문에서 추출한 조건으로 후보를 좁힐 수 있고, 애매하면 복수 문서를 읽거나 확인을 요청한다. 운영에서는 데이터 수정이나 권한 변경 후 인덱스를 동기화하고, 조회 직전 원본 버전도 대조할 수 있다. 자료가 갱신되지 않은 상태에서 모델만 바꿔도 같은 옛 출처가 들어갈 수 있어서, 적재와 검색과 생성 결과를 따로 평가했다. [블로그의 기억 정정과 검색 반영](/agentic-ai/memory-lifecycle/)
